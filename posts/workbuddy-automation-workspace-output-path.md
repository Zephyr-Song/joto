# WorkBuddy 自动化任务开始前，为什么要先固定工作空间和结果保存位置？

WorkBuddy 自动化开始前，应先固定允许读取的工作空间、结果保存目录和命名规则。提示词相同并不代表执行条件相同：目录决定 Agent 能接触哪些本地文件，保存位置决定结果能否被找到、复核和归档。先把“从哪里读、向哪里写、怎样命名”写清楚，才能避免任务读错批次、覆盖旧文件或产出完成后无人知道结果在哪里。

## 为什么一句“每天汇总最新数据”还不够？

企业把日报、周报或文件整理交给自动化时，往往只描述业务目标，例如“每天九点汇总昨天的销售数据并生成报告”。这句话没有说明源文件位于哪个目录、怎样判断“昨天”、是否包含临时文件、结果覆盖还是新增，以及历史结果保留多久。

手动操作时，员工会凭目录习惯找到文件；自动触发时，任务只会在配置的执行条件内工作。腾讯云官方文档明确把“工作空间”定义为任务执行目录及文件保存位置，并说明本地文件读写仅发生在用户指定的工作目录范围内。因此，工作空间不是一个可忽略的技术字段，而是输入与输出边界。

## 旧方法为什么容易造成“结果有了，但不能用”？

把所有文件放在同一个大目录，看起来最省配置，却会把原始数据、草稿、上期结果和临时文件混在一起。任务可能把自己昨天生成的报告再次当作今天的输入，也可能在同名文件上直接覆盖，导致无法比较两个周期的变化。

另一个常见问题是只在提示词中写“保存报告”，没有约定目录与文件名。任务即使完成，接收人仍要搜索文件；多人协作时，更难判断哪一份是最新正式结果、哪一份只是中间产物。

## 怎样把工作空间拆成可验收的文件边界？

先定义**输入区**。只放本次任务允许读取的文件，并规定文件类型、日期口径和排除规则。源文件若会持续更新，可在触发前生成清单或快照，避免执行过程中输入变化。

再定义**处理中间区**。需要解压、转换、合并或生成临时文件的任务，不要直接在原始目录操作。中间区可以让失败后的残留文件与正式结果分开，也便于定位任务停在哪一步。

最后定义**结果区**。规定结果目录、文件格式和唯一命名方式，例如使用业务日期而不是运行日期，或在文件名中加入任务名称与版本。结果区只保留可交付产物和必要日志，不把缓存当成交付。

## 命名和覆盖规则要回答哪些问题？

至少回答四个问题：同一天重复运行是覆盖、追加还是生成新版本；空结果是否仍生成说明文件；部分失败时文件如何标记；历史文件由谁、在什么条件下归档或删除。

对周期任务，优先使用可追踪的命名方式，例如“任务名-业务日期-状态”。如果任务允许覆盖，必须先确认覆盖对象确实是可再生结果，而不是唯一原始资料。涉及删除或批量改写时，应保留人工确认或可恢复副本。

## 哪些场景不能只靠一个默认工作空间？

当任务同时读取多个部门资料、包含不同权限等级文件，或要把结果发送到外部平台时，单一大目录通常不足以表达边界。应进一步按部门、项目或数据敏感度拆分目录，并把跨目录读取和外发动作单独审批。

自动化页面默认分配工作空间可以帮助任务落地，但默认目录不等于业务已完成分类。企业仍要根据自己的资料治理、保留规则和协作方式确认是否需要调整。

## 怎样做一次可复用的目录验收？

准备一套最小样本：一份有效输入、一份应排除文件、一份同名历史结果和一个异常文件。运行任务后检查四项：是否只读取有效输入；是否忽略排除项；是否按约定处理同名结果；异常是否被记录而不是静默跳过。

随后让未参与配置的同事仅凭目录结构、文件名和日志找到本次输入与正式产物。如果他仍需要询问“到底用了哪份文件”或“哪份才是最终版”，工作空间和保存规则还没有达到可交付状态。
