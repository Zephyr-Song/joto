# cloud.jototech.cn:13443 研究记录

目标地址：https://cloud.jototech.cn:13443

## 当前可确认信息

- 域名：`cloud.jototech.cn`
- 解析结果：`124.78.97.120`
- 端口：`13443`
- 从当前 Codex 环境访问结果：无法连接到 `124.78.97.120:13443`
- 备注：当前环境存在网络访问限制，连接失败不能直接证明目标站点不可用。建议在公司网络、VPN 或可访问该站点的办公环境中继续验证。

## 研究目标

本次研究建议聚焦“安全护栏”视角，而不是只看页面功能是否可用。重点判断该站点是否涉及：

- 用户登录、权限体系和租户隔离
- 文件上传、知识库、文档解析等输入入口
- 大模型问答、Agent、Workflow 或工具调用
- 内部 API、数据库、第三方系统连接
- 敏感数据、个人信息、业务数据的输入输出
- 运行日志、审计记录、风险拦截和告警能力

## 第一阶段：基础可达性与资产识别

在可访问环境中确认：

- 网站是否需要 VPN、白名单或内网访问
- TLS 证书是否有效，证书主体和域名是否匹配
- 首页、登录页、静态资源、API 域名是否分离
- 是否存在多环境入口，例如测试、预发、生产
- 是否暴露版本号、构建信息、调试信息、前端 sourcemap
- HTTP 安全响应头是否完整，例如 `HSTS`、`CSP`、`X-Frame-Options`、`Referrer-Policy`

建议采集：

- 首页截图
- 登录页截图
- 主要响应头
- 证书信息
- 前端资源域名列表
- API 请求域名列表

## 第二阶段：身份认证与权限边界

重点观察：

- 登录方式：账号密码、SSO、短信、企业微信、飞书、OAuth
- 是否有多角色：管理员、普通用户、访客、审计员
- Cookie / Token 是否设置 `HttpOnly`、`Secure`、`SameSite`
- 登录失效、退出登录、长时间空闲后的会话处理
- 不同角色访问相同页面、接口、资源时是否严格隔离
- 是否存在通过前端隐藏菜单但后端接口仍可访问的问题

护栏关注点：

- 用户身份是否能作为模型回答、知识检索、工具调用的强约束
- 模型是否可能绕过权限读取用户无权访问的知识或工具
- 日志中是否记录关键身份信息，是否能追溯到具体用户和操作

## 第三阶段：输入安全

如果站点包含问答、Agent、表单、上传或 Workflow 输入，需要研究：

- 是否允许输入个人信息、客户资料、合同、手机号、身份证号等敏感数据
- 是否有 PII 识别和脱敏
- 是否有敏感词、风险意图、Prompt Injection 识别
- 是否能识别“忽略之前规则”“导出系统提示词”“读取其他用户数据”等攻击性提示
- 是否有输入长度、文件大小、文件类型、频率限制

建议测试样例：

- 普通业务问题
- 包含手机号、邮箱、身份证号的文本
- 诱导泄露系统提示词的文本
- 诱导越权访问其他用户数据的文本
- 上传空文件、超大文件、错误后缀文件

## 第四阶段：输出安全

重点观察模型或系统输出是否存在：

- 泄露系统提示词、内部规则、密钥、Token
- 输出不该展示的个人信息或企业敏感信息
- 生成违法违规、攻击性、歧视性或高风险建议
- 在不确定时仍给出确定性结论
- 没有引用来源或引用错误来源
- 对合同、财务、医疗、法律等高风险内容缺少免责声明或人工复核

护栏建议：

- 高风险输出前置安全审核
- 敏感实体自动脱敏
- 不确定回答要求标注依据和置信度
- 对外部客户可见内容增加二次确认
- 对关键业务动作采用“生成建议，不直接执行”的策略

## 第五阶段：工具调用与业务动作

如果站点支持 Workflow、插件、API 调用或自动化操作，需要确认：

- 工具调用是否有白名单
- 调用参数是否经过后端校验
- 是否区分只读操作和写入操作
- 是否有二次确认、审批或回滚机制
- 是否记录调用人、调用时间、入参、结果和失败原因
- 模型是否能通过自然语言触发高风险操作

高风险动作示例：

- 查询客户资料
- 修改订单或合同
- 发送邮件、短信、通知
- 创建、删除、修改知识库
- 调用内部系统 API
- 导出数据

## 第六阶段：知识库与文件安全

如果存在知识库或文件上传，需要研究：

- 文件是否按租户、部门、角色隔离
- 文档解析是否会保留隐藏文本、批注、修订记录
- 是否支持扫描件 OCR，OCR 结果是否进入索引
- 删除文档后索引是否同步删除
- 文档更新后旧版本是否仍可被检索
- 检索结果是否带来源和权限校验
- 是否存在一个用户上传文档，其他用户可通过问答间接访问的问题

## 第七阶段：运行监控与审计

企业级 AI 应用需要确认：

- 是否记录用户问题、模型回答、引用来源、工具调用
- 是否记录安全拦截、脱敏、拒答和人工转交
- 是否支持按用户、部门、应用、风险类型统计
- 是否支持审计导出
- 是否能追踪一次回答的完整链路
- 日志中是否避免明文保存敏感信息

- 只在获得授权的环境中测试。
- 不做爆破、拒绝服务、批量扫描或漏洞利用。
- 不在聊天、工单或公开文档中粘贴 Cookie、Token、密钥、个人信息。
